# 任务配方

任务配方是独立 personal.recipes 插件，保存你确认的原任务参数和执行版本。
再次使用时核对或修改本次参数，创建新运行，保留它与配方、原结果的关联。
它复用任务目标，不复制模型决策、工具轨迹或历史环境。

## 本地体验

按[本地指南](LOCAL_DEVELOPMENT.md)启动。默认个人组合包含配方，无需额外模型：

1. 在「知识库」点击示例 API 迁移说明并检索原文。
2. 在成功结果中点击「保存为任务配方」。检查名称和带入的 JSON 参数，确认保存。
3. 在「任务配方」点击「使用配方」，核对参数，再点击「确认参数并运行」。
4. 查看新的执行记录；详情会显示配方来源、参数是否变化，并能打开原结果。

只想验证最小组合，在 backend 执行：

```sh
AGENT_PLUGINS_FILE=examples/plugins.recipes.yaml bun run dev
```

该组合只有示例 Markdown 来源与配方插件。根工作台可发起笔记检索，
成功后保存配方；不装配其他个人/团队能力。显式文件完全覆盖默认组合。

## 保存范围与隐私

默认支持已审查的个人读取任务：笔记/网页检索、引用回答、研究、网页收集、
引用复核、Context7、发布准备与显式授权的 MCP 读取路由。未装配的能力不会
被配方自动安装。团队写入、文档一次性暂存 ID 和资料收录默认不开放。
自定义 capabilities 为可信作者配置，名称不证明行为只读，须审查实际实现。

保存前核对成功根运行的单次执行凭证、输入序列化指纹和当前安装/Manifest。
原参数修改过、字段顺序不同、旧凭证缺失或多轮人工补充都可能不能保存；
请先用完整参数执行一次。新参数可在使用配方时修改，不覆盖原配方。

候选输入只在当前页面内存，最多 50 份、每份 32 KiB，不写浏览器持久存储。
刷新后丢失，可人工粘贴原 JSON，服务器仍核对指纹，不根据模型稿猜测。
确认保存后完整参数写入本机应用数据目录，可能包含个人正文或敏感字段；
保存前请检查。这不是自动脱敏、加密存储或 Secret 管理。

## 版本、重复提交与失败

运行前和 Runtime 实际解析后核对安装及 Manifest 指纹；插件移除、升级或绑定
变化时拒绝执行，需恢复原版本或重新运行后创建新配方。模型、知识内容、Tool
实现、配置与会话仍使用当前环境，因此输出可以变化。expectedExecution 仅约束
新的根执行，后续人工继续和子委派沿用正常协议。

相同请求 ID 与相同参数复用原 Trigger；换配方或参数后复用 ID 会冲突。
来源回执独立保存，写回执失败会返回已创建的真实 Run ID 和警告，不能假装
任务没有执行。未拿到 Run ID 的处理中状态会明确提示，不建议重复发起。

目前每个本机范围最多 50 个配方，暂未提供归档管理。移除插件关闭页面/API，
保留已保存配方和运行历史。当前是本机工作台，不提供多人服务认证。

[作者指南](PLUGIN_AUTHORING.md)。
