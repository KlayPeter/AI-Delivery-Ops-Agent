# 第三方平台接入配置指南

本文说明如何接入飞书、TAPD、大模型和外部 HTTP Agent。系统当前通过飞书长连接接收事件，不需要公网 Webhook。

## 1. 飞书机器人

### 1.1 创建应用

1. 打开 [飞书开发者后台](https://open.feishu.cn/app/)，创建企业自建应用。
2. 添加“机器人”能力。
3. 在“凭证与基础信息”中取得 App ID 和 App Secret。
4. 写入 `backend/.env`：

```dotenv
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=xxx
```

不要把真实 `.env` 提交到 Git。

### 1.2 开通权限

权限以飞书开放平台当前显示的名称和应用实际功能为准，至少需要：

- 接收群聊和私聊消息。
- 以机器人身份发送消息。
- 读取群与成员信息。
- 上传看板图片或文件时需要对应的文件上传权限。

只申请实际使用的权限。会议纪要、云文档或邮件功能未启用时，不要提前申请无关权限。

### 1.3 使用长连接

1. 在“事件订阅”中选择“使用长连接接收事件”。
2. 添加“接收消息”事件 `im.message.receive_v1`。
3. 创建版本并发布应用。
4. 把机器人加入测试群。
5. 启动后端，日志出现飞书 WS 就绪信息后再进行联调。

长连接由后端主动连接飞书，因此内网环境不需要 ngrok、公网 IP 或事件回调 URL。

### 1.4 获取 Bot Open ID

配置 App ID 和 App Secret 后执行：

```bash
cd backend
bun run get-bot-info
```

把结果写入：

```dotenv
FEISHU_BOT_OPEN_ID=ou_xxx
```

### 1.5 获取群 Chat ID

1. 把测试机器人加入目标群。
2. 在群内 `@机器人 测试`。
3. 从后端日志或管理台日志中确认事件的 `chat_id`，通常以 `oc_` 开头。
4. 在 `/config` 的群组配置中添加该群，并同步群成员。

## 2. TAPD

### 2.1 获取 API Token

由 TAPD 管理员创建 API 凭证，把 Token 写入：

```dotenv
TAPD_API_TOKEN=xxx
TAPD_WORKSPACE_ID=0
TAPD_WORKITEM_TYPE_ID=
```

当前 Adapter 使用 Bearer Token。若企业 TAPD 使用其他鉴权方式，需要先调整 Adapter 并在测试 Workspace 验证，不能把用户名和密码拼进 URL。

### 2.2 配置 Workspace

TAPD 项目 URL 中的数字通常是 Workspace ID，例如：

```text
https://www.tapd.cn/<workspace_id>/bug/
```

其中路径中的数字是 `workspace_id`。公开版默认值为 `0`，不会连接真实项目。
在自己的测试环境中同时确认：

- `tapd.workspace_id`
- `tapd.api_base`
- `tapd.workitem_type_id`

本地开发使用独立测试 Workspace，禁止对生产项目执行创建、状态修改或全量同步测试。

## 3. 大模型

系统通过 OpenAI 兼容接口调用模型：

```dotenv
AI_PROVIDER=openai
AI_API_BASE=https://api.openai.com/v1
AI_API_KEY=sk-xxx
AI_MODEL=
```

非敏感动态配置也可以在管理台维护：

- `ai.provider`
- `ai.api_base`
- `ai.model`
- `ai.max_tokens`
- `ai.temperature`
- `ai.retry_count`

如果开发环境需要代理，再配置：

```dotenv
LLM_USE_PROXY=true
HTTP_PROXY_URL=http://127.0.0.1:7890
```

不要在前端、Prompt、日志或动态配置中保存 API Key。

## 4. 外部 HTTP Agent

### 4.1 接入边界

外部 Agent 是独立服务，不把第三方源码加载进机器人主进程。当前 Host 只开放 HTTP Runtime，并强制：

- 使用 HTTPS。
- URL 不包含用户名和密码。
- Endpoint 主机出现在 Manifest 的 `requirements.networkHosts`。
- Secret 只使用 `env://ENV_NAME` 引用。
- Agent 不能直接向飞书发送消息。
- Host 限制超时、响应体大小和允许的 Artifact 类型。

### 4.2 请求协议

Host 向 Endpoint 发送 `POST`：

```json
{
  "protocolVersion": "1.0",
  "request": {
    "runId": "run-id",
    "scope": {
      "workspaceId": "default",
      "botInstanceId": "default"
    },
    "capability": "knowledge.ai.hot.fetch",
    "input": {
      "date": "2026-07-15",
      "limit": 10,
      "language": "zh-CN"
    },
    "deadlineAt": "2026-07-15T10:00:00.000Z",
    "traceContext": {}
  },
  "installation": {
    "id": "install-external-agent",
    "config": {}
  }
}
```

Agent 返回：

```json
{
  "status": "succeeded",
  "data": {},
  "artifacts": [
    {
      "type": "markdown",
      "mediaType": "text/markdown",
      "schemaVersion": "1.0",
      "content": "# 今日内容"
    }
  ]
}
```

### 4.3 安装 AIHot Agent

如果 Endpoint 不需要 Token：

```bash
curl -X POST http://localhost:8090/api/agents/ai-hot/install \
  -H 'Content-Type: application/json' \
  -d '{"endpoint":"https://agent.example.com/run"}'
```

如果需要 Token，先把真实值注入后端环境：

```dotenv
AI_HOT_TOKEN=xxx
```

安装时只传引用：

```bash
curl -X POST http://localhost:8090/api/agents/ai-hot/install \
  -H 'Content-Type: application/json' \
  -d '{
    "endpoint":"https://agent.example.com/run",
    "apiTokenRef":"env://AI_HOT_TOKEN"
  }'
```

查看 Agent：

```bash
curl http://localhost:8090/api/agents
```

手动验证：

```bash
curl -X POST http://localhost:8090/api/agents/run \
  -H 'Content-Type: application/json' \
  -d '{
    "capability":"knowledge.ai.hot.fetch",
    "groupId":"oc_xxx",
    "input":{"date":"2026-07-15","limit":10,"language":"zh-CN"},
    "triggerId":"ai-hot-smoke-20260715"
  }'
```

`triggerId` 应保持业务唯一。重复使用同一个 ID 会命中幂等保护并返回已有执行。

### 4.4 启用定时推送

在目标群的动态配置中启用 AIHot 模块，并配置 `ai_hot` 调度时间。先完成一次手动运行，确认文章 URL、内容和目标群正确，再打开定时任务。

## 5. 部署安全要求

当前控制面 API 没有应用层登录和 RBAC，只支持可信网络或受保护的反向代理。
必须满足：

- 后端端口只对管理网段开放。
- 不把 `/api/agents/install` 和 `/api/agents/run` 暴露到公网。
- 通过防火墙、Ingress 或反向代理限制来源。
- 外部 Agent Endpoint 使用内部 DNS、证书和最小网络白名单。
- 定期轮换飞书、TAPD、AI 和 Agent Token。

如果系统未来跨网段、开放公网或交给更多管理员，必须先增加身份认证、RBAC、操作审计和速率限制。

## 6. 联调验收

按顺序验证：

1. `GET /healthz` 返回 `{"ok":true}`。
2. 飞书 WSClient 建立连接。
3. 测试群 `@机器人` 能收到回复。
4. 测试 TAPD 能创建和更新 Story。
5. 大模型能完成一次意图解析或日报生成。
6. `GET /api/agents` 能看到所选插件的 Agent；默认组合为七个内置 Agent。
7. 外部 Agent 手动运行成功，结果发送到指定测试群。
8. 使用相同 `triggerId` 重复运行，不产生重复投递。

架构和协议详情见 [《Agent 架构升级与系统评估（2026-07）》](Agent架构升级与系统评估-2026-07.md)。

## 7. Agent 插件装配

可在后端环境变量中指定 `AGENT_PLUGINS_FILE=profiles/agents/team.yaml`；未指定时使用默认八个功能插件、七个 Agent。会议纪要插件仍受原模块开关控制。配置支持内置 ID、部署者审查的本地适配模块和已安装的 npm 包，未启用的外部模块不导入。配置文件路径以启动目录解析，模块的相对路径以配置文件目录解析。

该配置选择 Agent/Tool/Skill 以及消息指令、引用上下文和帮助提示；移除任务插件也需移除依赖它的编排插件。页面、业务 API、调度和飞书连接尚未全部随插件关闭。完整插件边界、原生代码信任要求及模板见[功能插件规范 v1](PLUGIN_AUTHORING.md)。
