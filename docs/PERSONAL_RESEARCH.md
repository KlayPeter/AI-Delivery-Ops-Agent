# 个人研究助手

默认个人工作台包含独立 personal.research 插件。它使用你的模型规划资料子任务，
整理当前知识、明确的公开网页及已装配文档/发布能力；父子运行、原始资料和研究稿
分别保存。它不是无模型检索的改名，也不会自动证明研究稿正确。

## 本地使用

按[本地运行](LOCAL_DEVELOPMENT.md)启动，在「连接与模型」配置自己的模型并
重启后端，再打开「研究助手」。没有模型时可继续使用「知识库」原文检索。

可从这样的任务开始：

> 查找 API 迁移说明相关笔记，整理发布前必须确认的事项，区分原文要求和你的建议。

研究助手可调用当前 Markdown/Obsidian、资料库来源或 Web 来源检索，委派
knowledge.answer 核验回答的引用，以及收集明确的公开 URL、检查给定历史运行的
引用变化。Context7 和 GitHub 发布准备只有实际装配时才会出现在可选委派中；
不会因为任务中提到某个仓库或服务而自动安装它。

问题与取回的资料、来源元数据会发送给你配置的模型。子知识问答也可能调用模型，
不是一次固定费用的单模型生成。父循环最多八步、四次已记录委派、180 秒，
子任务有自己的限制并受父截止时间约束；真实费用取决于所选服务。

## 查看证据

结果首先说明已核对的资料子任务，再展示模型整理和原始资料。索引记录真实子
Run/Artifact ID，可打开子任务核对。若没有成功的资料查询/回答，父任务不能把
一段模型文字当作已完成研究；空稿不能交付，失败子任务和被拒绝的 RAG 引用不计资料。
有其他成功资料时可以完成，但索引保留失败状态和 partial 警告。仍在运行或等待回复
的子任务会阻止完成，不能被父模型的一段总结跳过。

有资料记录仍不证明资料充分。空检索、资料不足和工具失败必须结合原始结果判断；
父研究稿的 summaryVerification 始终为 not_verified。知识问答子任务检查引用身份
和精确引文，仍不自动证明语义支持；父模型的推论需要你复核。

可在「结果验收」选择「研究稿与子任务资料索引」，检查保存的最终稿、索引、
私有标记和执行凭证。选择器区分多份 JSON 产物，缺少或重复索引都失败；原始资料
保留。结构通过不等于研究结论正确。

## 人工继续与组合

缺少目标或范围时，助手可以暂停提问；在运行详情补充回复，继续同一 Run。
已用委派次数从持久化步骤恢复，不能靠暂停取得新额度。会话保存问题与回复，
不保证完整重放工具消息；必要时需在剩余额度内重新读取资料。

显式插件文件仍完全替换默认组合。Markdown 研究插件入口为
backend/src/agents/personal-research/plugin.ts，Web 变体为 webPlugin.ts；
两者都依赖对应来源、knowledge.answer、knowledge.capture、knowledge.impact。
页面由插件贡献，移除后关闭，旧历史保留。完整边界见[功能卡](../backend/src/agents/personal-research/FEATURE.md)。

## 验证范围

自动测试使用真实 AI SDK、本机 OpenAI 兼容模拟端点和实际专业子 Agent，
覆盖检索、RAG 引用核验、两次委派、部分失败恢复、未结束子任务、暂停继续、额度恢复和完成拒绝。
这证明协议和执行链路，不证明真实模型的规划能力、成功率、耗时、成本或用户采用。
