# 项目部署与开发协作流程

本文描述公开仓库的通用开发和部署边界，不绑定某个公司、集群、Registry 或
发布平台。

## 分支与变更

1. 从默认分支创建短生命周期分支。
2. 保持改动聚焦，并为行为变化更新对应 `FEATURE.md`。
3. 只使用虚构测试数据和本地测试凭证。
4. 提交前完成代码检查、测试、构建与秘密扫描。
5. 通过 Pull Request 审查后再合并。

禁止提交 `.env`、数据库、日志、生成报告、私有域名、真实人员或项目 ID。

## 本地验证

后端：

```bash
cd backend
bun install --frozen-lockfile
bunx prisma generate
bunx prisma validate
bun run typecheck
TEST_DATABASE_PATH="$(mktemp)"
DATABASE_URL="file:${TEST_DATABASE_PATH}" bunx prisma db push --skip-generate
DATABASE_URL="file:${TEST_DATABASE_PATH}" bun test
```

前端：

```bash
cd frontend
pnpm install --frozen-lockfile
pnpm lint
pnpm typecheck
bun test
pnpm build
```

仓库：

```bash
git diff --check
docker compose -f docker/docker-compose.yml config
```

## 公共 CI

`.github/workflows/ci.yml` 只执行质量检查：

- 后端 Prisma 校验、类型检查和测试；
- 前端 lint、类型检查、测试和构建；
- Docker Compose 配置与前后端镜像构建；
- 基础秘密扫描。

CI 不推送镜像、不连接 Kubernetes，也不部署任何环境。

## 本地 Docker

```bash
cp backend/.env.example backend/.env
docker compose -f docker/docker-compose.yml up --build
```

默认端口仅绑定 `127.0.0.1`。应用没有内置鉴权；如果需要远程访问，应由带
身份验证的反向代理提供 TLS、访问控制和限流。

## Kubernetes

公共清单位于 `deploy/k8s/`，只提供中性模板：

- namespace 为 `delivery-ops`；
- 镜像地址和凭证使用 `CHANGE_ME`；
- 后端固定为单写实例；
- 公共仓库不包含自动部署工作流。

部署者负责自己的镜像 Registry、Secret Manager、Ingress、NetworkPolicy、
证书、备份和恢复演练。详见 `deploy/k8s/DEPLOY.md`。

## SQLite 边界

- 只能有一个后端写实例；
- 数据目录必须持久化；
- 备份需要覆盖 SQLite 数据库及必要的 journal/WAL 状态；
- 多写实例或高规模查询应先迁移到适合的数据库，而不是直接扩容 Pod。

## 发布建议

使用不可变版本号和镜像标签。发布说明至少包含：

- 用户可见变化；
- 数据库或配置迁移；
- 已运行的测试；
- 已知限制与回滚方式；
- 安全影响。

本项目的公共 CI 只证明候选代码通过质量门禁，不代表某个部署环境已经安全。
